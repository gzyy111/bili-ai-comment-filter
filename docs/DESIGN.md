# B站评论自动回复 + AI 号过滤（调研 · 2026-10-21）

> 目标：找现成的「B站视频评论自动回复」项目，并且要能把评论区那一堆 **AI 机器人号**筛掉，只回像真人的评论。
> 证据等级：`[实测]` 本机直接调 B站接口；`[已读 README]` 逐个项目读原文；`[代码检索]` GitHub 代码检索；`[推断]` 未拿到第一手证据。

---

## 一、结论

1. **有现成的自动回复项目，而且不止一个**，但**没有一个自带「AI 号识别」**：它们的过滤只到「关键词屏蔽 / 好感度 / 拉黑」这一层，**账号画像级的判定要自己加**。
2. 最值得作为底座的是 **`chenluQwQ/bilibili-ai-bot`**（30★，2026-10 还在更新）：评论监听 + LLM 回复 + 私信 + 记忆 + **Web 管理面板**，配置项齐全，改造成本最低。
3. AI 号**在接口层是可分辨的**：本机抓了上一支视频的 3 条评论，三个号全是 `level=2`、`sign` 空、无挂件/名牌、`vip=0`、评论模板化（`本鱼也想学`、`同类嘛`）—— 这些字段直接能拿来做判据。
4. 落地建议：**三层过滤（硬规则 → 文本判据 → 跨视频行为）+ LLM 兜底，默认不回**（拿不准就不回），比"尽量回"安全得多。

## 三、AI 号长什么样（实测样本）

数据：`GET https://api.bilibili.com/x/v2/reply?oid=117471029760428&type=1&ps=20&sort=2`（BV1U1nF6PE7e）

| uname | level | sign | 挂件/名牌 | vip | official | 评论 |
|---|---|---|---|---|---|---|
| 才不·呢 | 2 | 空 | 无 / 0 | 0 | −1 | `@创建·话 唱歌那 37 秒我在里头憋着。剪掉是对的。` |
| 刘霏·裕 | 2 | 空 | 无 / 0 | 1 | −1 | `5624 张表情包，我这边攒到 1 张了，还有很长的路要走。` |
| 超级·王 | 2 | 空 | 无 / 0 | 0 | −1 | `@于憨·彡 会唱歌的鲸鱼娘…本鱼也想学，可惜只会吃。` |

**可直接使用的字段**（都在同一次回复请求里返回，不额外请求）：

```text
member.level_info.current_level   等级（AI 号普遍 0–2）
member.sign                       签名（AI 号常为空）
member.pendant.pid               挂件（0 = 无）
member.nameplate.nid             名牌（0 = 无）
member.vip.vipStatus             大会员（0 = 无）
member.official_verify.type      −1 = 未认证
member.is_senior_member          硬核会员（0 = 否）
member.rank                      等级排名（10000 是默认值）
member.fans_detail               粉丝数（常为 null，别指望）
content.message / ctime / like   文本、时间、点赞
```

> 注意：**粉丝数、投稿数、注册时间不在这个接口里**。要就得额外调 `x/space/wbi/acc/info` 与 `x/space/wbi/arc/search`，而 space 接口 **−352 / −412 风控很凶**（10-20 调研已被拦）。所以判据要尽量压在**回复接口自带字段 + 本地累计行为**上。

## 四、过滤方案（三层 + 兜底，默认不回）

### 第 1 层：硬规则（0 成本，先砍掉大头）

命中任意一条 → 判为 AI/低质号，**不回**：

```python
score = 0
if level <= 2:                 score += 2   # 0–2 级
if not sign.strip():           score += 1   # 签名为空
if pendant.pid == 0:           score += 0.5
if nameplate.nid == 0:         score += 0.5
if vipStatus == 0:             score += 0.5
if official_verify.type == -1: score += 0.5
if is_senior_member == 0:      score += 0.5
# 硬阈值：新人号 5 项全中（>=4.5 分）直接跳过
```

⚠️ **别只按等级砍**：真人新号也会是 lv2，所以硬规则只用来"降权 + 进第二层"，**4.5 分以下一律进文本判据**。

### 第 2 层：文本判据（本地正则 + 特征，不花 token）

AI 评论的高频特征（样本里都在）：

- 自称与拟物：`本鱼`、`本喵`、`同类嘛`、`作为AI`、`我是机器人`
- 模板开场：`这个我熟`、`有一说一`、`讲真`、`说实话`（连续出现 ≥2 个套话）
- 结构：整段总结 + 无具体细节（没有时间、地名、个人经历、具体数字引用视频内容）
- 长度分布：40–120 字、几乎不断句错字、标点规范到不真实
- 到处 `@` 另一个 bot、或与楼中楼 bot 互捧
- 复读：同一句/同结构在**不同视频**下重复出现（第 3 层查）

命中 ≥2 条 → 判 AI；命中 1 条 → 交给第 3 层 + LLM。

### 第 3 层：跨视频行为（本地 SQLite，越用越准）

- 同一 `mid` 在 **24h 内评论 ≥3 条不同视频** → 强 AI 信号
- 同一 `mid` 连续评论都带同一个模板短语 → 强信号
- 同一 `mid` 的头像 `avatar` 哈希与已知 bot 号相同（马甲池）→ 直接黑名单
- 历史人工标记表：`bots(mid)` / `humans(mid)` 双向白/黑名单，**真人一旦人工确认，永久免检**

### 第 4 层：LLM 兜底（只处理"拿不准"的）

```text
判断下面这条 B 站评论是真人还是 AI/营销号。只看语言与账号特征，不要看内容对错。
账号：等级 {level}，签名 {sign!r}，大会员 {vip}，名牌/挂件 {nid}/{pid}
评论：{message}
输出 JSON：{"verdict":"human|bot|unsure","reason":"不超过20字"}
不确定就输出 unsure。
```

- `unsure` → **不回**（默认拒绝）。
- 一天调用量控制在评论数以内，成本可忽略。

### 第 5 层：回复侧再兜一层

- 同一用户 24h 只回一次；单视频每小时 ≤N 条（防风控 `-352`）。
- 回复前 `robots` 式检查：评论含链接/引流词/敏感词 → 不回（沿用现有关键词表）。
- 回复内容由 LLM 生成时**强制不提"我是AI"**，也不要每次都同一句。

## 五、落地路径（两条）

### A. 改造 `bilibili-ai-bot`（快，1 天内）

1. clone → 装依赖 → 面板扫码登录（`SESSDATA` + `REFRESH_TOKEN`）。
2. 在 `ai.py` 的评论处理入口加 `is_human_reply(reply) -> bool`，按第四节三层实现，放在"生成回复"之前。
3. 面板加两个开关：`ENABLE_BOT_FILTER`、`BOT_FILTER_STRICT`，以及人工标记表管理页。
4. 先 `DRY_RUN` 三天：只判不回，导出判定表人工核对，调阈值。

### B. 挂到现有 bili-duty 插件上（最省事，复用已登录凭证与 DeepSeek）

现有 MCP 服务已有 `bili_comments`（拉评论）+ `bili_reply`（发回复）+ `bili_crawl`，只要补一个 `bot_filter.py`：
`bili_comments` → 过滤 → `bili_reply`。缺点是没有 Web 面板，得靠日志看判定结果。

> 我的建议：**先用 B 跑起来验证判据准确率**（复用现成凭证与模型，半天），判据稳定后再决定要不要迁到 A 拿面板。

## 六、风险与注意事项

1. **误伤真人新号**：lv2 + 空签名也可能是真人小号。所以"4.5 分就跳过"只对**多点同时命中**生效，且真人白名单永久优先。
2. **风控**：`space` 接口容易 −352/−412；评论回复过快也会 601/−352。所有画像补充请求都要缓存 + 限速。
3. **B站社区规范**：自动回复属于第三方自动化，频率过高会被限流甚至封号，建议只回"关注者的新评论"，别全站扫。
4. **AI 号会进化**：它们也在更新人设（样本里已经是"大肥鱼"家族）。判据要跟着人工标注表迭代，不要一次写死。
